# 密讯 CipherChat · Debian 12 手把手安装教程

> **一套端到端 AES-256-GCM 加密的即时通讯 + 隐私网盘系统**
> 服务器零知识：数据库与磁盘上只有密文，密码/密钥永远不离开你的浏览器。
>
> 本教程专为 **Debian 12** 编写，所有端口均为**非标端口**，
> 与你已被 Reality 协议占用的 80/443 **完全共存、互不干扰**。

## 一、架构与端口规划

### 1.1 工作原理（30 秒版）

```
 你的浏览器                                你的 Debian 12 服务器
┌─────────────────────┐                  ┌──────────────────────────────────┐
│  输入 频道ID + 密码   │   密文(HTTPS/WS) │  Caddy 网关  :2053  ← 唯一对外的口 │
│  ↓ PBKDF2 31万轮     │ ───────────────►│   ├─ 普通请求 → Next.js  :13000     │
│  ↓ AES-256-GCM 加密  │                  │   └─ XTransformPort → 中继 :13003   │
│  只有密文离开浏览器   │ ◄─────────────── │  SQLite(密文) + 磁盘分块(密文)      │
└─────────────────────┘                  └──────────────────────────────────┘
        服务器从头到尾不知道你的密码，也解不开任何一条消息、任何一个文件
```

- **聊天**：频道 ID + 密码 → 浏览器本地派生加密密钥；同频道同密码的设备进入同一房间
- **网盘**：随机 8 位 ID + 个人密钥 → 每把密钥对应一个独立加密仓库
- **实时性**：WebSocket 长连接中继，消息 / 在线设备 / 「正在输入」毫秒级同步

### 1.2 端口占用表（重点：避开 80/443）

| 端口  | 用途            | 监听范围       | 说明                          |
|-------|-----------------|----------------|-------------------------------|
| 80    | （你的 Reality） | —              | 本系统**不占用**              |
| 443   | （你的 Reality） | —              | 本系统**不占用**              |
| 2053  | Caddy 对外网关  | `0.0.0.0`      | 网站入口，可自定义             |
| 13000 | Next.js 主程序  | `127.0.0.1`    | 仅本机，外网摸不到             |
| 13003 | WebSocket 中继  | `127.0.0.1`    | 仅本机，经网关转发             |

> 2053 是 Cloudflare 支持的 HTTPS 备用端口，将来想套 CF 也方便；不喜欢可换成任何空闲端口（如 8443、2087…），教程后文有说明。

### 1.3 服务器要求

- Debian 12（amd64 / arm64 均可）
- 最低配置：1 核 CPU / 1GB 内存（构建时需要 swap，安装器会自动帮你加）
- 磁盘：系统 2GB + 你的聊天文件和网盘文件的实际容量
- 能访问外网（安装 Bun / Caddy 时需要）

cd /root

ls /root/cipherchat   # 应能看到 package.json、deploy、src 等文件

## 三、方式一：一键安装（推荐，约 5 分钟）

安装器会自动完成：装 Bun → 装 Caddy → 建用户 → 部署到 `/opt/cipherchat` → 初始化数据库 → 生产构建 → 注册并启动全部 systemd 服务 → 健康检查。

全程日志同步写入 `/var/log/cipherchat-setup.log`，任何一步失败都会明确提示出错位置与排查命令，不会无声退出。

```bash
cd /root/cipherchat
sudo bash deploy/setup.sh
```

安装过程中只有一处可能询问你：**内存不足时是否自动创建 2GB swap**，直接回车同意即可。

## 四、方式二：手动逐步安装（理解每一步）

适合想清楚知道每一步在做什么的用户。效果与一键安装完全一致。

### 步骤 1：安装基础工具

```bash
apt update
apt install -y curl unzip tar rsync
```

### 步骤 2：安装 Bun 运行时

Bun 是本系统的 JavaScript 运行时（能直接跑 TypeScript，部署最省心）：

```bash
export BUN_INSTALL="/opt/bun"
mkdir -p /opt/bun
curl -fsSL https://bun.sh/install | bash
ln -sf /opt/bun/bin/bun /usr/local/bin/bun

# 验证
bun --version        # 应输出版本号，如 1.3.x
```

### 步骤 3：安装 Caddy 网关

Caddy 负责：对外只暴露一个非标端口，把请求转发给内部两个服务：

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --batch --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' > /etc/apt/sources.list.d/caddy-stable.list
apt update
apt install -y caddy

caddy version       # 应输出版本号
```

### 步骤 4：创建运行用户与目录

```bash
useradd --system --home-dir /nonexistent --shell /usr/sbin/nologin cipherchat
mkdir -p /opt/cipherchat/{db,data}
```

### 步骤 5：复制代码

```bash
rsync -a --exclude 'node_modules' --exclude '.next' \
  /root/cipherchat/ /opt/cipherchat/
```

### 步骤 6：写配置文件

```bash
cat > /opt/cipherchat/.env <<'EOF'
DATABASE_URL=file:/opt/cipherchat/db/custom.db
DATA_DIR=/opt/cipherchat/data
WS_PORT=13003
MAX_CHAT_FILE_BYTES=1073741824
MAX_DRIVE_FILE_BYTES=5368709120
DRIVE_QUOTA_BYTES=21474836480
SESSION_TTL_MS=604800000
EOF
```

> 各参数含义：聊天单文件上限 1GB、网盘单文件 5GB、每仓库总配额 20GB、登录会话 7 天。都可以改。

### 步骤 7：修正属主（重要，勿跳过）

rsync 复制过来的文件属于 root，而后续安装/构建要以低权限 cipherchat 用户执行，
**必须先授权，否则会报 `EACCES: permission denied`**：

```bash
chown -R cipherchat:cipherchat /opt/cipherchat
chmod 700 /opt/cipherchat/db /opt/cipherchat/data
chmod 600 /opt/cipherchat/.env
```

### 步骤 8：安装依赖 + 初始化数据库 + 构建

```bash
cd /opt/cipherchat

# 屏蔽宿主 shell 可能残留的同名环境变量，防止 prisma 写错数据库位置
export DATABASE_URL="file:/opt/cipherchat/db/custom.db"
export DATA_DIR="/opt/cipherchat/data"
export WS_PORT=13003

# 安装依赖（以 cipherchat 用户身份，不污染 root；失败时可加 NPM_CONFIG_REGISTRY=https://registry.npmmirror.com）
runuser -u cipherchat -- env HOME=/tmp bun install

# 初始化 SQLite 表结构（生成 /opt/cipherchat/db/custom.db）
runuser -u cipherchat -- env HOME=/tmp bun run db:push

# 生产构建（1-3 分钟）
runuser -u cipherchat -- env HOME=/tmp NODE_ENV=production bun run build

# 验证关键产物是否生成
ls .next/standalone/server.js .next/standalone/node_modules/.prisma db/custom.db
```

### 步骤 9：注册 systemd 服务（开机自启 + 崩溃自动拉起）

**9.1 Web 主服务** —— 新建 `/etc/systemd/system/cipherchat-web.service`：

```bash
cat > /etc/systemd/system/cipherchat-web.service <<'EOF'
[Unit]
Description=CipherChat Web (Next.js)
After=network.target

[Service]
Type=simple
User=cipherchat
Group=cipherchat
WorkingDirectory=/opt/cipherchat
EnvironmentFile=/opt/cipherchat/.env
Environment=NODE_ENV=production
Environment=PORT=13000
Environment=HOSTNAME=127.0.0.1
ExecStart=/usr/local/bin/bun /opt/cipherchat/.next/standalone/server.js
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal
SyslogIdentifier=cipherchat-web

[Install]
WantedBy=multi-user.target
EOF
```

**9.2 WebSocket 中继服务** —— 新建 `/etc/systemd/system/cipherchat-relay.service`：

```bash
cat > /etc/systemd/system/cipherchat-relay.service <<'EOF'
[Unit]
Description=CipherChat WebSocket Relay
After=network.target cipherchat-web.service

[Service]
Type=simple
User=cipherchat
Group=cipherchat
WorkingDirectory=/opt/cipherchat
EnvironmentFile=/opt/cipherchat/.env
Environment=NODE_ENV=production
ExecStart=/usr/local/bin/bun /opt/cipherchat/mini-services/relay/index.ts
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal
SyslogIdentifier=cipherchat-relay

[Install]
WantedBy=multi-user.target
EOF
```

**9.3 启动两个服务：**

```bash
systemctl daemon-reload
systemctl enable --now cipherchat-web cipherchat-relay

# 查看状态（两个都应是 active (running) 绿色）
systemctl status cipherchat-web cipherchat-relay --no-pager
```

### 步骤 10：配置 Caddy 网关

```bash
# 备份原有配置（如果你之前用过 caddy）
[ -f /etc/caddy/Caddyfile ] && cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak

# 写入本系统网关配置（监听 2053）
cat > /etc/caddy/Caddyfile <<'EOF'
:2053 {
        @transform_port_query {
                query XTransformPort=*
        }

        handle @transform_port_query {
                reverse_proxy localhost:{query.XTransformPort} {
                        header_up Host {host}
                        header_up X-Forwarded-For {remote_host}
                        header_up X-Forwarded-Proto {scheme}
                        header_up X-Real-IP {remote_host}
                }
        }

        handle {
                reverse_proxy localhost:13000 {
                        header_up Host {host}
                        header_up X-Forwarded-For {remote_host}
                        header_up X-Forwarded-Proto {scheme}
                        header_up X-Real-IP {remote_host}
                }
        }
}
EOF

systemctl enable --now caddy
systemctl restart caddy
```

### 步骤 11：本机自检

```bash
curl http://127.0.0.1:13000/api/health    # → {"ok":true,...}
curl "http://127.0.0.1:13003/?EIO=4&transport=polling"   # → 返回一段 JSON 即中继存活
curl http://127.0.0.1:2053/api/health     # → {"ok":true,...}（经网关）
```

三条都有响应 = 部署成功。

## 五、防火墙放行

### 5.1 云服务商安全组

到你的云控制台（阿里云/腾讯云/AWS/Vultr…）→ 安全组 / 防火墙规则 → **放行 TCP 2053**（或你自定义的网关端口）。

> 只放行 2053 就够了！13000 / 13003 只监听本机回环，外网本来就访问不到，**不要**放行它们。

### 5.2 如果服务器启用了 nftables/ufw

```bash
# ufw 用户
ufw allow 2053/tcp

# nftables 用户（Debian 12 默认未启用，一般无需操作）
nft list ruleset | grep -q 2053 || nft add rule inet filter input tcp dport 2053 accept
```

## 七、日常使用指南

### 7.1 加密聊天

- **进入频道**：频道 ID 随便编（字母/数字/`-`/`_`），密码就是加密密钥。把这两个告诉朋友，他们即可进入同一房间。
- **消息状态**：发送中转圈圈 → 送达显示单勾 ✓ → 对方阅读后变双勾 ✓✓（Telegram 式）。**对方可用 `/readtip off` 关闭自己的已读回执**（关闭后其阅读不再向你回执）。
- **快捷指令**（输入框以 `/` 开头，本地处理不进入消息流）：
  - `/help` 查看全部指令
  - `/readtip on|off` 开/关已读回执
  - `/nick <新昵称>` 实时修改昵称（频道内所有人可见）
  - `/clear` 清空本频道记录 · `/leave` 离开频道
  - `/admin <超级密钥>` 验证管理员身份（错误即拒）
  - `/stats` 查看服务器统计（需管理员：消息/文件/网盘数量与容量、运行时长）
  - `/destroy <自毁密钥>` 在聊天内直接触发全局自毁
- **发文件**：点回形针、或**直接 Ctrl+V 粘贴**截图/文件、或拖拽到输入框，全自动分块加密上传（单文件最大 1GB，可在 `.env` 调大）。
- **回复/复制/删除**：点一下任意气泡呼出菜单。**频道内任何人**都可以删除单条消息或清空整个频道（含全部文件），操作结果均有弹窗提示。
- **设备面板**：顶部「N 台设备在线」可查看每台设备的型号、系统、浏览器、IP 与归属地 —— 这是服务器从连接层识别的，**无法被客户端伪造**。
- **忘记密码 = 数据作废**：密码丢了谁也解不开历史消息（包括你和服务商），这是零知识设计的代价与保证。

### 7.2 隐私网盘

- **首次初始化（重要）**：部署后第一次进入网盘页会要求设置两把密钥：
  - **管理员超级密钥** —— 之后任何人想「新建网盘」都必须提供它，防止陌生访客随意创建仓库占满你的硬盘；
  - **自毁密钥** —— 紧急开关，在任何密码框（频道密码 / 网盘个人密钥 / 超级密钥）输入它，会**立即销毁服务器上全部聊天记录、文件与网盘数据**（不可恢复、无需二次确认）。两把密钥均只存哈希、无法找回，请抄写保存在密码管理器里。⚠️ 部署后请第一时间完成初始化，防止他人抢先设置。
- **新建**：切到「新建网盘」→ 输入管理员超级密钥 + 个人密钥 → 系统生成随机 8 位 ID → 确认创建 → **立即抄写 ID 与密钥**（弹窗里也可一键复制）。
- **解锁**：输入 ID + 个人密钥（无需超级密钥 —— 解锁已有仓库是用户自己的事，只有「创建」才需要管理员授权）。ID 错/密钥错都会被拒绝；**密钥不同看到的仓库完全不同**。
- **容量**：单文件最大 5GB，每仓库默认 20GB（`.env` 里 `DRIVE_QUOTA_BYTES` 可调）。超大文件浏览器会尝试「流式下载到磁盘」（Chrome/Edge 桌面版），不占内存。
- **防滥用**：每 IP 每小时最多生成 12 个 ID、创建 3 个仓库；创建还需管理员超级密钥，机器人刷不动。

### 7.3 关于「相同频道 ID + 不同密码」

这是正常且刻意的设计：实际频道号 = `SHA-256(频道 ID + 密码派生哈希)`，密码不同就是两个互不可见的独立房间（可否认性设计）。服务器永远不会告诉任何人「密码错了」，所以打错密码会静默进入一个空频道 —— 界面上遇到「频道已就绪」却预期有历史消息时，请先检查密码。网盘同理：同一 ID + 不同密钥 = 不同仓库。

### 7.4 安全模型（知其所以然）

- 消息与文件元数据使用 **AES-256-GCM** 加密，密钥由 **PBKDF2-SHA256（310,000 轮）** 从你的密码派生，盐值绑定频道/网盘 ID。
- 服务器数据库里只有密文与不可逆哈希（本仓库 `scripts/` 下的验证脚本可自行复现验证）。
- 登录令牌（token）只出现在 HTTP 头部，数据库只存其 SHA-256 哈希，**所有服务日志都不打印 token 与消息内容**。

## 八、运维：日志 / 备份 / 升级 / 卸载

### 8.1 日志

```bash
journalctl -u cipherchat-web   -n 100 --no-pager   # Web 最近100行
journalctl -u cipherchat-relay -f                   # 中继实时日志（可放心展示，无敏感信息）
journalctl -u caddy         -n 50 --no-pager
```

### 8.2 备份与恢复（一条命令）

```bash
bash /opt/cipherchat/deploy/backup.sh              # 备份 db + data + .env
# 恢复：
systemctl stop cipherchat-web cipherchat-relay
tar -xzf /opt/cipherchat-backups/cipherchat-backup-XXXX.tar.gz -C /opt/cipherchat
chown -R cipherchat:cipherchat /opt/cipherchat
systemctl start cipherchat-web cipherchat-relay
```

> 建议加个每日自动备份 crontab：`crontab -e` 加入
> `0 4 * * * bash /opt/cipherchat/deploy/backup.sh`

### 8.3 升级新版本

```bash
cd /root
tar -xzf cipherchat-v1.x.x.tar.gz -C /tmp/newver
rsync -a --exclude node_modules --exclude .next --exclude db --exclude data --exclude .env /tmp/newver/cipherchat/ /opt/cipherchat/
chown -R cipherchat:cipherchat /opt/cipherchat   # ★ 先投权，再降权构建
cd /opt/cipherchat
runuser -u cipherchat -- env HOME=/tmp bun install

### 9.2 套 Cloudflare（免费 HTTPS + 隐藏源站 IP）

1. 域名托管到 Cloudflare，添加 `A` 记录指向服务器 IP（开橙色云）
2. Cloudflare → SSL/TLS → 模式选 **Flexible**（或 Full + 下节自签证书）
3. Cloudflare → Network → 确保 **WebSockets = ON**
4. 访问 `https://你的域名:2053/` —— 完成
   （2053 是 CF 支持的 HTTPS 端口；也可用 2083/2087/2096/8443）

> 说明：即使不套 HTTPS，你的消息/文件在本系统里**本来就是端到端加密的**；HTTPS 保护的是「进入频道之前的页面本身不被篡改」。建议有域名就套 CF。

### 9.3 直接给 Caddy 上自动证书

80/443 被 Reality 占用，Let's Encrypt 的 HTTP/TLS 验证用不了，需要 **DNS 验证**。以 Cloudflare 为例：

        acme_dns cloudflare {env.CF_API_TOKEN}
}
# :2053 改为：
chat.你的域名.com:2053 {
        ...（其余不变）
}
```

```bash

systemctl restart caddy
```

## 十、常见问题 FAQ

**Q1：和 Reality（80/443）真的不冲突吗？**
不冲突。本系统只对外监听 2053（可改），内部 13000/13003 只绑 127.0.0.1。安装前后 `ss -tlnp | grep -E ':(80|443)\ '` 你会看到 Reality 一直在。

**Q2：国内服务器安装 Bun / 依赖很慢或失败？**
给安装器挂镜像源重试（注意用 `sudo env` 传变量）：
```bash
sudo env NPM_REGISTRY=https://registry.npmmirror.com bash deploy/setup.sh
```
Bun 本体下载慢的话：开代理再跑，或从 GitHub Releases 手动下载 bun-linux-x64.zip 解压到 `/opt/bun/bin/bun`，然后重新执行安装脚本。

**Q3：构建时报 JavaScript heap out of memory？**
内存不够。安装器在内存 <1.4GB 时会主动帮你加 2GB swap；手动装的话：
```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```
然后重跑构建。

**Q4：网站打得开但「连接已断开，重连中」/ 消息发不出去？**
中继服务或网关转发问题，依次查：
```bash
systemctl status cipherchat-relay
curl "http://127.0.0.1:13003/?EIO=4&transport=polling"
journalctl -u cipherchat-relay -n 30 --no-pager
```
若用了 Cloudflare，确认 Network 里 WebSockets 已开启。

**Q5：设备面板里 IP 归属地为「未知地区」？**
IP 库（ipwho.is / ip-api.com）暂时不可达或被墙。不影响聊天功能；服务器重启或网络恢复后自动补上（有 7 天缓存）。

**Q6：频道密码/网盘密钥忘了怎么办？**
没办法，这是设计使然——服务器从未存过密钥。聊天换个新频道即可；网盘里的旧数据相当于被销毁。

**Q7：别人乱进我的频道怎么办？**
密码强度就是一切：频道 ID 可以告诉别人（类似房间号），密码务必 12 位以上混合字符。怀疑泄露就全员换新频道+新密码（旧消息用旧密码仍可解，注意旧密码也已泄露就等于公开了）。

**Q8：手机上用体验如何？**
全站 HTML5 自适应 + 安全区适配，iOS Safari / 微信内置浏览器 / Android Chrome 均可流畅使用。可以直接「添加到主屏幕」当 App 用。

**Q9：重启服务器后要手动启动吗？**
不用。三个服务均已 `systemctl enable`，开机自启、崩溃自动拉起。

**Q10：怎么彻底确认服务器看不到我的内容？**
```bash
# 数据库里全是密文：
sqlite3 /opt/cipherchat/db/custom.db "SELECT payload FROM ChatMessage LIMIT 3;"
# 磁盘文件也是密文：
xxd /opt/cipherchat/data/chat/$(ls /opt/cipherchat/data/chat | head -1)/000000.bin | head -3
```
另外项目自带验证脚本 `scripts/e2e-crypto-verify.mjs`，可用相同密码独立复现解密全过程。

## 从 v1.1.2 升级到 v1.2.0（手把手）

你遇到的「无法进入频道 / importKey 报错」正是 **HTTP 明文访问**导致浏览器禁用加密 API —— 升级并配置 HTTPS 即可根治，聊天记录全程保留：

```bash
# 1. 上传并解压新版
tar -xzf cipherchat-v1.3.0.tar.gz
cd cipherchat

# 2. 数据保留式升级（自动备份 → 同步代码 → 数据库演进 → 构建 → 重启）
sudo bash deploy/upgrade.sh

# 3. 升级脚本会自动询问是否配置 HTTPS；如当时跳过了，稍后随时：
sudo bash deploy/https.sh
#    推荐选择：
#    · 有域名且 DNS 托管在 Cloudflare → 模式 2（全自动续期，不占用 Reality 的 80/443）
#    · 无域名 → 模式 1 自签名（浏览器首次访问点「高级→继续访问」即可）

# 4. 浏览器访问 https://你的域名或IP:2053/ （注意是 https://）
```

日常运维指令速查：

```bash
sudo bash /opt/cipherchat/deploy/upgrade.sh    # 升级到新版（数据保留）
sudo bash /opt/cipherchat/deploy/https.sh      # 重新配置/更换证书
sudo bash /opt/cipherchat/deploy/backup.sh     # 手动备份
sudo bash /opt/cipherchat/deploy/uninstall.sh  # 卸载（先自动备份）
```

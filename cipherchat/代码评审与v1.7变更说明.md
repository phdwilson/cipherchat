# 代码评审与 v1.7 变更说明

> 评审对象：CipherChat v1.6.0 全量源码（约 1.2 万行 TS/TSX）
> 评审方式：全量通读 + 服务端/客户端双路并行深审 + 浏览器端到端验证
> 结论先行：**架构健康、密码学实现扎实，但存在 15 处可被实际利用的安全缺陷与 12 处高影响性能/健壮性问题**，全部已在 v1.7.0 修复，并新增 5 个玩法。

## 一、总体评价

**做得好的地方（v1.6 已具备）：**

- 密码学设计正确：PBKDF2-SHA256 310k 轮派生、AES-256-GCM 每消息独立 IV、文件分块 AAD 绑定 `fileId:index` 防重排、认证哈希与加密密钥分离。
- 会话令牌只存 SHA-256 哈希、所有密钥比较使用 `timingSafeEqual`、分块写入 tmp+rename 原子落盘、已读回执单事务批量写入。
- 诚实的错误信息（不向客户端泄露内部细节）、日志零密文零 token 的安全约定贯彻得很好。
- v1.6 修复日志（缺块坏流、presence 泄露等）说明项目有持续审计习惯。

**主要问题（按严重度）：** 见下表，全部已在 v1.7.0 修复（服务端 15 项 / 客户端 12 项 / 新功能 5 项）。

## 二、服务端安全缺陷（v1.7.0 全部修复）

| # | 缺陷 | 位置 | 修复 |
|---|------|------|------|
| 1 | **跨频道已读回执泄露**：`chat:readers` 仅按 messageId 查询，任何成员可探测其他频道消息的读者列表与阅读时间 | relay `chat:readers` | join `ChatMessage` 并限定 `channelKeyId` |
| 2 | **IP 伪造绕过全部限流**：无条件信任 `X-Real-IP`/`XFF`，直连后端端口时可轮换伪造头 | `geo.ts` / `api.ts` / relay | 新增 `TRUST_PROXY` 开关，`off` 时回退 TCP 对端地址 |
| 3 | **TURN 长期凭证公开下发**：静态凭证随 `/api/config` 发给任何访问者（开放中继滥用/流量盗用） | `/api/config` | 凭证仅由专用限流端点签发，客户端按需获取 |
| 4 | **磁盘填充绕过**：允许 40000/100000 块 × 4MiB（理论 160–400GB）而只校验 1/5GiB 声明值 | chat/drive init | 分块上限由字节上限推导 + 交叉校验一致性 |
| 5 | **权限 fail-open**：发送的角色检查抛异常时按允许处理 | relay `persistAndRelayMessage` | fail-closed |
| 6 | **轮换无权限门**：旁听也能发起/完成轮换并吊销全频道会话 | `/api/chat/rotate` | start/finish 需 owner |
| 7 | **私聊实为全房间广播**：所有成员可收到他人 whisper 信封与 from/to 元数据 | relay `chat:whisper` | 按 pubId 单播；语音/私聊开关 relay 强制执行 |
| 8 | **取消轮换孤儿文件**：只删 `ready=false` 行，已就绪文件磁盘被清但记录留存（消息在但文件永久打不开） | `invites.ts cancelRotation` | 统一整行删除 |
| 9 | **邀请并发兑换超限**：maxUses「先查后增」竞态 | `invites.ts redeemInvite` | 条件 `updateMany` 原子抢占 |
| 10 | **主密钥竞态双行**：`getInviteKey` 并发首建产生两行 ServerSecret，邀请密文不可解 | `invites.ts` | findMany 收敛到最早一行 |
| 11 | **历史接口 500**：`?limit=abc` → NaN 直传 Prisma；`?before=garbage` → Invalid Date | `/api/chat/history` | 严格参数校验 |
| 12 | **网盘配额漂移**：usedBytes 读-改-写在并发 complete/delete 下丢失更新 | drive routes | `$increment`/`$decrement` 原子化 |
| 13 | **半成品上传永久残留**：`cleanupStaleUploads` 是死代码从未被调用 | relay | 每小时定时清理 + 删孤儿行 |
| 14 | **自毁漏清语音状态**：wipe 后被毁频道仍广播语音参会者并持有内存 | relay wipe 轮询 | 同时清空 voice/lobby 状态 |
| 15 | **PRAGMA 竞态**：WAL/busy_timeout 未 await 即首查 | `db.ts` / relay | 暴露 ready promise，监听前 await |

另：`chat:nick` 补 15 次/10 秒限流（此前可无限触发全频道 presence 查询+广播）、geo 内存缓存加上限、drive init/chunk/complete 补限流、TURN 端点会话优先限流。

## 三、客户端缺陷与性能（v1.7.0 全部修复）

| # | 问题 | 位置 | 修复 |
|---|------|------|------|
| 1 | **整店订阅重渲染风暴**：上传进度/typing/presence 任一变化重渲染全部气泡与输入栏 | Composer/ChatScreen/MessageBubble 等 6 处 | 细粒度 selector + useShallow + `React.memo` |
| 2 | **回复预览 O(n²)**：每气泡各自 `messages.find()` | MessageBubble | ChatScreen 统一构建 Map 传入 |
| 3 | **socket 置空竞态崩溃**：await 加密/上传期间 `leave()` 置空 socket → `null.emit` TypeError | store 全部发送路径 | 局部捕获 + 15s ack 超时（不再永久卡「发送中」） |
| 4 | **历史跨频道串台**：慢响应把旧频道消息并入新频道 | `loadHistory` | join/leave 纪元（epoch）守卫 |
| 5 | **密钥轮换重进串频道**：rejoin 未传 connectionMode，relay 用户被丢进 `-p2p-mode` 幽灵频道 | ChatScreen `rejoinWithPassword` | 透传 mode |
| 6 | **删除无回滚**：删除/清空失败时本地已移除、服务端还在 | store | 快照回滚 |
| 7 | **内存无界增长**：messages 不裁剪、头像每气泡重复解密、reportedReadIds 无限累积 | store/MessageBubble | 2000 条上限 + 头像解密缓存（128）+ Set 修剪 |
| 8 | **串行解密**：成员面板/网盘逐条 await WebCrypto | MembersSheet/drive.ts | Promise.all 并行 |
| 9 | **图片挂载即解密**：翻历史时几十张图并行下载解密（15MB 阈值过高） | FileBubble | 阈值 5MB + IntersectionObserver 懒触发 |
| 10 | **按住说话卡死**：录音中 disabled 吞掉 pointerup，60s 内无法松开发送/上滑取消 | Composer | 不禁用 + setPointerCapture |
| 11 | **井字棋身份误判**（新功能首版缺陷）：棋子归属按当前消息 sender 判定，双人走子后双方视角反了 | ChatScreen/ToyBubble | 按 `challengerId` 判定 |
| 12 | 杂项：草稿逐键写 localStorage、解密失败渲染空气泡、`maximumScale:1` 禁缩放（WCAG）、TTS voices 首次为空、保存好友可抛异常、语音暂停进度归零、`timeAgo` 负数 | 多处 | 全部修复 |

## 四、v1.7.0 新增玩法

1. **加密投票 `/poll`**：题目选项随信封整体加密；服务端新增 `ChatPollVote` 表只存「谁投了第几项」（与 emoji 回应同级元数据）；实时计票条、可改票、旁听禁投、历史还原。
2. **井字棋对战 `/ttt`**：走子即加密消息，旧盘只读、最新盘可交互；`validateTttMove`/`judgeTttBoard` 纯函数全量单测；双浏览器实测完整对局至胜利。
3. **闪照**：init 带 `viewOnce` 标记；首个下载者原子锁定 `viewOnceBurnedAt`，流读完**真实删除**磁盘分块与记录；脚本实测首看 200 / 再看 404-410。
4. **全屏特效 `/confetti` `/fireworks`**：纯 Canvas 2D 粒子系统（零依赖），全员同屏，每条消息只播一次。
5. **心情状态 `/mood`**：随 presence 加密广播，成员面板徽章展示。

# v1.8.0 代码评审与变更说明

## 一、本次核心问题定位（用户报告：150MB 文件后台显示 4MB）

**根因实验复现**（scripts/test-dirsize.mjs）：`dirSizeBytesAsync` 的 `total += (await stat(...)).size` 在 Bun 运行时下存在丢失更新竞态 —— 38 个分片并发 stat，读-改-写被拆开交错，最终只剩 1~2 块大小；十次重复实验结果在 2~4MiB 间随机波动，完美解释用户观察。对照组（串行 for-of / 同步 statSync / 先求值再累加 / sizes 数组 reduce）全部精确返回 150.00MiB。

**修复**：映射函数内不读写共享变量，`Promise.all` 求出 size 数组后 `reduce` 求和 —— 与并发调度时机完全无关。复现脚本回归：上传 150MB 后，会话 usedBytes、文件行 totalBytes、管理端 driveBytes、磁盘 du 四处全部精确一致；三连发压力测试全部通过。

**存量数据**：代码修复不能自愈历史坏数据，新增 `recalc-drive-usage` 维护动作（以磁盘为唯一事实来源重写统计 + 清理幽灵行）。端到端场景验证：注入 4MB 坏统计 → 自检发现（偏差 146MB）→ 一键重算 → 复查转绿 → 管理端恢复 150MB。

## 二、静默失败清单（本次全部补齐原因+修复方式）

| 位置 | 旧行为 | 新行为 |
|------|--------|--------|
| ChatJoin 加入频道 catch | 裸抛英文 e.message | explainError 翻译：标题｜原因｜处理 |
| chat.ts loadHistory `!res.ok` | 静默 return | toast（区分 401 过期/429 限流/其他） |
| connectSocket `connect_error` | 未监听，永远「连接中」 | 首次失败 toast 原因+三步指引，恢复自动重置 |
| drive.ts refresh `!res.ok` | 静默 return（旧列表伪装成最新） | toast + 401 自动锁定 |
| drive.ts uploadFiles catch | 一句 e.message | 条目 + toast 双通道带原因 |
| DriveScreen doDownload/Preview | `catch { /* ignore */ }` 完全静默 | 完整提示；用户主动取消不误报 |
| VoiceBubble autoplay 拒绝 | `catch(() => {})` | 提示自动播放策略 + 点击重试即恢复 |
| VoiceBubble `<audio>` | 无 onError | 解码失败提示（编码不受支持） |

| tts.ts speakText | 两处静默 | 不支持/引擎异常 toast |

## 三、一键自检系统架构

- **引擎**：`src/lib/server/selfcheck.ts` —— `CHECK_REGISTRY` 注册表（12 项），`runSelfCheck(ctx, only?)` 入口，任何检查抛异常都转为 fail 结果（引擎级兜底）。
- **真实世界测试**：`checkUploadPipeline` 通过 HTTP 自调用 `req.nextUrl.origin` 走完整网盘生命周期（含逐字节下载比对与统计精确性断言）；`checkFilestoreIo` 真实写读校验删除；`checkRelayWs` TCP + engine.io 握手；TURN TCP 探测。
- **限流友好**：建仓 429 时优雅降级为 warn「非故障」；自检端点自身 6 次/10 分钟限流。
- **修复动作**：维护端点扩展 `recalc-drive-usage` / `cleanup-orphan-files` / `vacuum-db`（与既有 cleanup-sessions / revoke-sessions / backup 并列）；纯环境项（TURN 未配置等）明确无 action、只给教程。
- **UI**：`SelfCheckPanel.tsx`（红绿灯分组卡片 + 指标 + 折叠明细 + 一键修复按钮 + 修复后单项复查 + JSON 导出）；AdminScreen 新增「自检」页签；维护页新增三个一键动作。
- **CLI**：`scripts/doctor.mjs` —— PBKDF2 派生与网页端完全一致（同参数实测互认），`--fix-all` 修复后自动复查。
